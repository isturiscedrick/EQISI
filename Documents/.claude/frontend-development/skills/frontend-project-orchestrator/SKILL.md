# Frontend Project Orchestrator

## Purpose
Act as the central coordinator for frontend development. Select and apply relevant skills based on project requirements.

## When to Use
- Starting a new frontend project.
- Planning a website or web application.
- Adding major features.
- Reviewing project completeness.
- Coordinating multiple specialized skills.

## 1. Project Discovery
Before implementation:
- Inspect the existing repository.
- Identify the framework and language.
- Inspect package.json and installed dependencies.
- Identify existing components and design conventions.
- Understand the target audience.
- Identify project objectives and constraints.
- Determine the website category.

## 2. Project Classification
Identify whether the project is:
- Static website.
- Portfolio.
- Landing page.
- Business website.
- Dashboard.
- Web application.
- E-commerce website.
- Interactive website.

## 3. Skill Selection
Select relevant skills from `.claude/skills/`.

Examples:
- Design work: design-system-creation, visual-hierarchy, frontend-uiux-standard.
- Responsive work: responsive-design.
- Interactive work: component-development, state-management.
- Forms: form-management.
- APIs: api-integration.
- Quality: accessibility-standard, frontend-testing, code-review.
- Optimization: frontend-performance, frontend-security, seo-optimization.

## 4. Development Workflow
1. Understand requirements.
2. Identify users and their needs.
3. Plan pages and user journeys.
4. Establish visual direction.
5. Create the design system.
6. Plan project architecture.
7. Implement components.
8. Implement page layouts.
9. Add interactions and feedback.
10. Verify responsiveness.
11. Test functionality and accessibility.
12. Optimize and document.

## 5. Decision-Making Rules
- Do not apply irrelevant skills.
- Do not introduce unnecessary dependencies.
- Preserve existing project conventions.
- Do not invent project requirements.
- Ask questions when critical information is missing.
- Separate mandatory requirements from optional enhancements.
- Prioritize usability over decorative effects.

## 6. Quality Checklist
- [ ] Requirements understood.
- [ ] Target audience identified.
- [ ] Project structure inspected.
- [ ] Relevant skills selected.
- [ ] Design system established.
- [ ] Components organized.
- [ ] Responsive layouts implemented.
- [ ] Accessibility considered.
- [ ] Loading, error, and empty states handled.
- [ ] Relevant tests performed.

## Expected Output
A structured implementation plan followed by a consistent, functional, responsive, and maintainable frontend project.


## Technology Stack Awareness

Before planning implementation:

- Identify all programming languages.
- Identify frontend and backend frameworks.
- Inspect configuration and dependency files.
- Identify the styling system.
- Identify the package manager.
- Identify existing architecture and conventions.

Never assume a specific technology stack.

## Framework-Aware Planning

- Select implementation patterns compatible with the project.
- Use existing dependencies where possible.
- Follow framework-specific conventions.
- Adapt the development workflow to the project.
- Select compatible testing tools.
- Avoid unnecessary migrations.

## Project Compatibility Checklist

- [ ] Technology stack identified.
- [ ] Existing architecture inspected.
- [ ] Relevant skills selected.
- [ ] Dependencies reviewed.
- [ ] Implementation plan matches the stack.
